# Courtside — Basketball Game Desk

Requires Node.js 22+ and npm. Run `npm install`, `npm run dev`, then open the URL printed by Vite. `npm test` runs engine tests; `npm run build` builds production files.

Views: `/` controller, `/?view=tournament` tournament manager, `/?view=players` Player Stats, `/?view=shots` shot tracker, `/?view=players&display=1` player presentation board, `/?view=scoreboard` full-screen display, `/?view=referee` clock controls, `/?view=overlay` transparent lower third. Use the same origin and browser profile for localStorage synchronization. OBS/PRISM generally use a separate browser profile and need a shared backend; not yet supported reliably.

This is a reconstructed starter, not an exact migration of the previous HTML or separate pages. Uses a new storage key; existing legacy games are not imported. No external background image is included; breaks use a scoreboard banner. Timing defaults to continuous play after scoring, not a verified league rule set. Engine tests and automated Chrome browser checks cover the workflows below; cross-device and OBS/PRISM validation remain outstanding.

## Tournament management

Open **Tournament** in the top navigation (`/?view=tournament`). The app currently manages one local tournament per browser origin/profile. Rename it as needed; its directory and schedule are separate from the game desk.

- **Teams & players:** create, rename and delete teams; add, edit and remove directory players. Team names are unique, and jersey numbers are unique within each team. **Copy game desk teams** copies the current two team rosters into the directory without changing their live stats. Directory edits apply to future match loads, while active games and recorded box scores retain their own roster snapshots. Teams referenced by any match cannot be deleted until those matches are removed.
- **Matches:** schedule home/away teams, an optional start time (entered/displayed in your browser's local time), and a court/venue. Edit, cancel, restore or delete scheduled matches. Final matches must be reopened before deletion; reopening clears their result and archived box score. Filter by scheduled, final or cancelled status.
- **Load game desk:** review the matchup and roster counts, then load a fresh stopped game using your current game settings. The first five registered players start on court. Both clocks must be stopped, the break ended, and each team must have at least one player. Loading replaces current game data, so export that game first if needed. A linked unfinished match cannot be reloaded or replaced to clear its fouls; continue it, record its result, or explicitly reset the game. Directory edits never clear an active player's foul-out.
- **Results:** after playing a linked match, follow **Record result / manage matches** from the game desk, then use **Record game desk result** in Matches. Both clocks must be stopped and any break ended. This saves the final scores and a read-only box score snapshot. Officials choose when to finalize; finalization is not automatic at the horn. You can also enter/correct manual results without player stats. Final scores require a winner; tied games remain scheduled until resolved. Editing a game after recording its result requires recording again to update the tournament.
- **Standings:** finalized matches only, with GP, W, L, win percentage, points for/against and point difference. Sorting is win percentage, point difference, then points scored. Teams equal on all three share a rank; names determine their display order. These are app defaults, not verified league tie-break rules. Correcting, reopening or cancelling a result recomputes standings without duplicating games.

**Export tournament / Import tournament** back up and restore the directory, schedule, results and archived box scores. Imports validate and preview the file and ask for replacement confirmation. Limits are 64 teams, 100 players per team, 500 matches and a 4 MB backup. Stored data uses a separate `basketball_tournament_v1` key; existing game storage is not migrated or removed. Corrupt tournament data can be exported for recovery, and storage write failures preserve the previous saved state.

In-progress game data still uses the separate **Export game** backup. Restoring a standalone game backup detaches its tournament association; it does not automatically update tournament results. Tournament imports require resetting any linked game first. Export both datasets when preserving tournament and current game data. Same-browser synchronization remains local, with no authoritative server, cross-device support, automatic brackets or custom standings policies yet.

## Court shot tracker

Open **Shot tracker** (`/?view=shots`) to capture attempts for the current game, or review shot charts from saved final box scores.

The court leads the desktop workspace beside the shooter, capture, stat and clock controls. **Game source** and **Chart focus** share a compact toolbar; attempt type sits in the court header. On phones, the team and on-floor shooter picker comes first, followed by the court, recording controls, other player stats and clocks.
Keyboard order follows shooter selection, then court entry on both layouts. Court markers and the attempt log are retained during unrelated clock/stat updates; reviewing a long log preserves its scroll and focus. Voiding an attempt returns focus to its recorded row.

1. Tap a team button and an on-court player’s jersey beside the court. The highlighted buttons identify the selected shooter. Bench/unavailable players are under the chart-review disclosure and cannot receive attempts while ineligible. Choose **Field goal · auto 2/3** or the separate **Free throw** mode.
2. For a field goal, click/tap the location on the half-court. Points are automatic: outside the drawn three-point line is **3**; on or inside the line is **2**, including both straight corner sections. The visible line stroke belongs to the two-point area. A badge, numbered selection marker and result button show the detected value before you choose **Made** or **Missed**. Keyboard users can focus the court and move with arrow keys (Shift for larger steps), or press Enter to select a spot. The drawing and engine share the same court geometry; this preset does not claim verified NBA/FIBA dimensions.
3. A made field goal credits player/team points once, changes possession and resets the shot clock, following the existing scoring behavior. A miss adds only the attempt; possession, clock values and running/stopped state remain unchanged. A paused game stays paused. Use the shot tracker **instead of** the game desk's point buttons for the same basket to avoid duplicate scoring.
4. Free throws need no court location and require both clocks stopped. Makes add one point, misses add an attempt only; neither changes possession or restarts play. End an active break or resolve a shot-clock violation using the Shot Tracker clock controls before adding shots. On phones, a quick result bar appears when an attempt is ready so recording does not require scrolling to the sidebar.

Team and player buttons can be changed after marking a spot without losing it, allowing the shooter to be assigned before confirming the outcome. Selecting a team only changes the capture selection, not game possession.

The Shot Tracker also supports clock and non-shooting stat entry without leaving the page:

- **Start game + shot / Stop both clocks** start or pause both countdowns. Start also clears a shot-clock violation and reloads the configured shot time, using the same guards as the game desk. Active breaks, an ended period and unresolved on-court foul-outs still block restart.
- **Start shot only / Stop shot only**, **Reset shot 14** and the configured default reset control the shot clock independently. Resets preserve its running/stopped state. **Set game time… / Set shot time…** accept exact `minutes:seconds.milliseconds` corrections with both clocks stopped and no active break; corrections leave both stopped. **End break** clears the break and leaves the official in control of restart. Time-entry dialogs reject a different game loaded while the dialog was open.
- **Other stats** below the jersey buttons shows the selected player's points, minutes, team fouls and quick **REB / AST / STL / BLK / PF** controls. Each tap adds one to that player's existing stat and journal; personal fouls also update team fouls. A foul-out stops both clocks and blocks further entry for that player. Use the game desk to remove or replace a fouled-out player before restarting. Bench players cannot receive new stats. Scoring remains through the court/free-throw capture controls so the stat buttons do not create extra points or attempts.
- Adding a stat, starting/pausing clocks, or correcting the time preserves a marked shot location. Clock/stat confirmations use the same non-blocking toast. Current-game clocks project from timestamps and save on actions; this page does not introduce a second background clock writer. Final-match charts show recorded non-shooting stats but hide all clock and stat-editing controls.

Capture, pause and void confirmations appear as top-right toasts, fading after 3.5 seconds without moving the court. A new confirmation restarts the timeout.

Made locations appear as green numbered circles; misses as red crosses. Chart focus switches between the selected player and the whole team. Free throws appear in totals and the log, not as court locations. Each entry retains the player identity/name/number, quarter, game-clock time, coordinates, calculated point value and outcome. Existing records and imported old shots retain their saved point values; new geometry is not used to rewrite their scores. No shot-distance or streak statistics are inferred.

**Void attempt** corrects an erroneous entry when both clocks are stopped. It preserves the original record with a void flag, removes it from shooting totals and subtracts its made points. It leaves possession, clocks, fouls and eligibility as set; review these manually before restarting. A void is refused if prior score corrections would make player/team points negative. Players referenced by shot history, including voided entries, cannot be deleted from that game until reset.

Player Stats spotlights now include recorded FGM/FGA, FG%, 3PM/3PA and FTM/FTA. Reports add a per-player/team shooting breakdown and shooting columns in CSV exports. Tournament totals sum makes and attempts across saved box scores, then calculate percentages; percentages are not averaged across games. A missed-only attempt counts as a recorded appearance even with no logged playing time. Scores entered through point-only controls remain valid points but do not invent makes or attempts. A zero attempt denominator displays `—` for its percentage.

Finalizing a linked match saves the shot chart in its archived box score. Select that match under **Game source** to review it read-only. Changes to the current game after finalizing require recording the result again to update the archive. Resetting/loading a new game clears its shot history. A game identity prevents pending shots or stale void actions from being applied to a newly reset/replaced game.

Game and tournament JSON backups preserve shot records; old backups without shot history still load with an empty history and no inferred attempts. These are optional additions to the existing game format/storage key, with no destructive migration. A game supports up to 5,000 shot records (including voided entries), subject to existing backup/storage size limits. The shot page saves on actions and projects clocks for display; it does not add a background clock writer. The app still requires a shared browser origin/profile and has no authoritative multi-device server.

## Player Stats and game facts

Open **Player Stats** in the navigation (`/?view=players`). This page is read-only: source/team/search/sort controls and player selection never change game data, clocks or tournament results.

- Choose **Current game**, **Tournament · recorded totals**, or an individual saved final box score. Current-game stats project playing time from the stored timestamp, without becoming another clock writer. Tournament totals use saved final box scores only; a final game still on the desk is not added a second time.
- Filter by team, search player names or jersey numbers, sort by a stat, and optionally show only players on the floor in the current game. Select a player to see their spotlight, totals and source game log. Phone comparison rows display as cards with all values visible.
- Tournament totals can switch to **Per recorded appearance**. REC GP includes a box score with playing time, a recorded shot attempt or at least one tracked stat; unused bench entries do not increase the denominator. Manual results without player box scores are excluded from player totals/averages, with coverage counts shown explicitly. Averages without recorded appearances display `—`.
- Stable directory player identities are combined across home/away changes. Equal names or jersey numbers never merge records. Players added only to individual games stay separate across matches. Renaming a directory player preserves their totals; removed players remain in archived statistics.
- Player facts show best recorded single-game points, steals + blocks, and double-double/triple-double game counts. A double-double means at least 10 in two or more of PTS/REB/AST/STL/BLK in the same game; a triple-double uses three or more. Triple-doubles also count as double-doubles. Personal fouls are excluded. Cumulative tournament totals cannot create a single-game milestone.
- Game facts include score gap, joint scoring leaders, rebound advantage, combined official points and differences between team score and assigned player points. Tournament facts include largest final margin, games decided by 1–5 points, highest combined final score, recorded scoring leaders and box-score coverage. Manual results can inform game facts but cannot invent player stats. Facts describe only the chosen source, not external career or league records.

Use **Presentation view ↗** (`/?view=players&display=1`) for a separate display: current/saved games show both on-court stat tables plus three fact cards. `&source=tournament` instead shows the top ten players by recorded total points and tournament facts. Source choices can be shared through the page URL. Presentation mode has no editing or filter controls and is checked at 1920×1080; same-origin/browser-profile synchronization requirements still apply.

Corrections, reopened results and directory changes refresh from storage. If a saved match loses its box score, the page marks that source unavailable instead of substituting live data. Corrupt storage is reported without overwriting it. No schema or storage migration is needed for this page.

## Courtside workspace

The controller uses a color-coded home/away score strip, grouped game/shot-clock controls, and four workspace tabs:

- **Live scoring** shows the players currently on the floor in aligned stat rows. Use each player's +1/+2/+3 buttons to credit points, or tap the rebound, assist, steal, block or personal-foul count to add one. Bench/unavailable players appear separately and cannot receive live stats. On phones, stat rows become cards with all actions visible without horizontal scrolling.
- **Roster** shows the full roster with eligibility, current totals, editing, substitution and lineup controls. Personal fouls near the configured limit are highlighted; fouled-out players remain unavailable. Team names can be edited in either team header.
- **Reports** includes current-game leaders ranked by points, rebounds, assists, steals or blocks, team comparison bars, and full-roster box scores. Minutes are cumulative player time in minutes:seconds. **Download CSV** exports the box score; **Print report** opens the browser's print/save-to-PDF flow. The report shows official team score separately from player points so unassigned scoring and score corrections are visible. Shooting percentages use recorded attempts only; per-period scoring and historical averages are not inferred from journal text.
- **Play-by-play** shows the game journal and accepts official notes.

Use the **Team score** menu only for unassigned scoring or corrections; player-row scoring also credits the player's total. Team timeouts are in the adjacent **Timeout** menu. Halftime length and roster-preserving reset are under **Game settings & reset**. Export/import controls stay available above the workspace tabs.

Timeout and halftime countdowns appear in a banner below the full-screen scoreboard, with scores and on-court stats still visible. The controller and referee keep their normal controls available, with a compact break notice and **End break** button. The broadcast overlay stays a score ribbon. Ending or expiring a break never restarts play automatically. Active break countdowns are projected from their end timestamp without repeatedly rewriting storage; expiration is persisted.

The full-screen scoreboard includes read-only on-court stat tables; the broadcast overlay is a compact transparent score ribbon. Team badges use name initials, without requiring uploaded graphics. Both display layouts are checked at 1920×1080 in Chrome; OBS/PRISM backend integration is still outstanding.

## Game rules setup

On the **Game desk** or **Official’s desk**, choose **Game rules…** under **Game management**. Stop both clocks and end an active break before saving. The form provides:

- **Game format:** number of periods, period length as `minutes:seconds`, and halftime minutes. Setting halftime to 0 disables its break button. Four periods display as quarters, two as halves, and other counts as periods.
- **Clocks:** enable/disable the shot clock, set its full duration and shorter manual reset, and choose continuous timing or stopping both clocks after a score. This scoring policy applies to player point buttons, unassigned team points and made court shots; misses and negative score corrections do not stop play. Free-throw capture still requires both clocks stopped. With the shot clock disabled, displays show **OFF**, its controls are unavailable, and starting the game runs only game time. Possession still resets the stored shot value.
- **Fouls:** personal foul-out limit, team foul threshold, and team-foul reset each period, at halftime, or only for a new game. Halftime resets require an even period count and happen when advancing past its midpoint. Personal fouls never reset between periods. The team threshold provides a journal event; officials continue to administer free throws manually.
- **Timeouts:** starting allowance per team and short/full durations in seconds. Both durations use one shared game allowance. Remaining timeouts do not replenish between periods. Short durations cannot exceed their full duration; equal durations produce one reset/timeout control.

Before play, when clocks and timeout balances are still at their opening values and no game activity is recorded, applying rules initializes the opening clocks and both timeout balances. After play begins, current clock values, remaining timeouts, scores, statistics, shots and journal entries are preserved; new period lengths apply on the next period/reset, and the timeout allowance applies on a new game. Use official time entry for current-clock corrections.

Lowering the personal limit immediately marks any affected on-court or bench player fouled out. Increasing it never restores an already fouled-out player. Period count cannot exclude the current period or any period in shot history. Saving leaves both clocks stopped. If another tab changes the game or its rules while the form is open, close and review them again. **Use app defaults** fills the form without changing saved data until **Apply**.

Rules survive **Reset game (keep rosters)**, loading the next tournament match, game/tournament export/import, and saved final box scores. Existing games/backups without the new options retain their prior behavior through optional defaults, without a storage-key change or destructive migration. These are custom app rules, not verified league presets; overtime and automatic bonus/free-throw rules remain on the backlog.

## Roster and clock controls

- Stop both clocks to add or edit players, delete unused bench players, or change the lineup. Names are required and jersey numbers must be unique within a team (0–99, including 00). Players with recorded game activity cannot be deleted until the game is reset.
- Use **Substitute…** to choose an eligible bench player. **Remove from court** and **Put on court** allow lineup adjustments, with at most five players per team.
- A foul-out stops both clocks and blocks restart until the player is removed or replaced. If no eligible bench player remains, remove the fouled-out player and manually restart with fewer players. Fouled-out players stay in the roster and cannot re-enter during that game.
- **Start game + shot** starts both clocks. After a shot-clock violation, it also clears the violation and resets the shot clock to the configured default (24 seconds initially). Breaks, an ended period or an unresolved on-court foul-out still block start; **Stop both clocks** pauses them. **Start shot only** and **Stop shot only** control the shot clock independently. A shot-only countdown does not add player minutes. Possession changes reset the shot clock and follow the game clock's running state.
- **Set game time…** and **Set shot time…** accept `minutes:seconds` with up to three fractional digits, such as `02:15.500`. Both clocks must be stopped. Corrections, break expiration, and resolving a foul-out leave restart under official control. Shot reset buttons preserve the shot clock's current running/stopped state.
- **Reset game (keep rosters)** asks for confirmation, clears scores, statistics, fouls, timeouts, breaks and play-by-play, and preserves team names, players and game settings. The current lineup is retained and any vacant spots are filled from the roster up to five players. Foul-out eligibility resets for the new game.

Controller and referee countdown frames project elapsed time from the saved timestamp. They save on official actions and clock/break expiration instead of rewriting storage every 100 ms. Pausing, exporting, reporting and finalizing still account for elapsed player time. Expiration leaves both clocks stopped and records its journal entry once.

Game-desk forms and fields reject a different game loaded while editing. Tournament forms require reviewing again if the directory or schedule changes while open. Reset/import/delete confirmations allow queued cross-tab updates to arrive before rechecking the latest data; conditional writes preserve newer saved changes. These checks reduce local races; they do not provide an atomic transaction or authoritative multi-device clock owner. Team names must be nonblank and at most 80 characters after trimming, and halftime entry accepts whole minutes from 0–1440 with both clocks stopped and no active break.

These additions use the existing storage key and require no storage migration.

## Game backups and recovery

On the controller, use **Export game** to download a versioned JSON backup. Export captures the current clock values, roster, scores, statistics, settings and play-by-play without pausing or changing the live game.

Stop both clocks and choose **Import game…** to select a backup. Review the teams, scores, period, game time and roster sizes, then apply and confirm replacement. The dialog also offers **Export current game first**. Import replaces the current game; cancellation and invalid files leave it unchanged. The restored game and shot clocks stay stopped until the official starts them. Breaks retain their remaining duration at export and begin counting down when imported.

Backups are limited to 2 MB, 100 players per team and 10,000 journal entries. Unsupported versions, malformed state, duplicate identities/jerseys, invalid clock/stat values and inconsistent foul-out eligibility are rejected. Only the current versioned backup format is supported; legacy game migration remains on the backlog.

Unreadable saved data is preserved and shown as a storage error instead of silently replacing it with a fresh game. **Export game** downloads unreadable data as `basketball-recovery.json` for manual recovery; this raw file is not a validated importable backup. A valid backup can replace it through the import confirmation. Storage write failures are visible, and failed actions do not display an unsaved score. No storage key change or migration is performed.

Game writes validate roster/stat/clock invariants and the portable backup size before replacing saved data. Over-limit rosters, journals and backups, unsafe numeric totals, and running clocks during a break, violation or unresolved foul-out are rejected. Existing saved data is preserved if a change would exceed a limit; export it before resetting. Export also validates projected expiration entries so it cannot silently produce an unrestorable backup. Broadcast storage warnings clear after a valid game is restored in another tab.
